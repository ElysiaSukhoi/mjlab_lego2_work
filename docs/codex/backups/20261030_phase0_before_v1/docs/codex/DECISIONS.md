## 2026-10-29：研究阶段的方向与边界

- **已确定目标**：部署actor盲走；当前本地actor仍输入高度，尚未符合目标。
- **已确定工作边界**：先研究和讨论，不改业务代码、不训练、不安装参考环境。
- **候选新路线**：中央坑、训练开始即有低高度课程、速度跟踪主导，尽量复用已有奖励；
  删除固定平台坐标的approach等shaping。用户尚要求先论证，未实施该路线。
- **候选最小扩展**：本体历史；若基线确实无法越障，再讨论不依赖地图x的局部接触反应。
  奖励使用训练真值不等于actor可读真值，部署可实现性需要单独审核。
- **纠正旧依据**：front_lift使用轮心高度，contact_advance未计算速度/位置增量，均不能
  把奖励均值提高当作成功抬腿/前移证据；不继续以此为依据堆叠奖励。
- **证据边界**：Dreamwaq有坑课程，也有高台yaw与历史估计器；不能归因为“只改通用奖励”。
  80cm能力、参考仓库课程等级和Lego2最终可爬高度不可互相等同。

研究依据见[交叉对比报告](/home/asus/work/Jiche_Project/高台训练/2026-10-29_盲走轮足高台开源对比报告.md)，

## 2026-10-29大体规划（历史；以正式v2为准）

详见 [REFACTOR_PLAN.md](REFACTOR_PLAN.md)。建议新建独立盲走坑式任务，保留旧任务；
先用普通PPO＋本体历史，不立即移植VAE或替换算法。阶段1观测，阶段2地形/出生/课程，
阶段3精简奖励与首轮短训，阶段4仅在基线不足时探索通用接触反应，阶段5全量与泛化评估。

- 计划要求首次正式训练前接通高度课程；这是设计要求，不代表当前已经实现。
- 先验证现有通用奖励基线，接触触发正z/抬轮只作可选对照，不是预先确定必加项。
- 5帧历史、3～30cm/10级、约3m升级距等是待验证候选，不记为已实现配置或最优参数。
- 观测改变后新run初始化；相同配置的长训可从该配置checkpoint继续，保留版本和实验归属。

## 不作未经证实的推断

- `Episode_Reward/upward=1` 只说明直立姿态奖励，不代表已经爬台。
- `platform_top_reached=0` 不能单独证明传感器错误；需结合 root x/z、接触和回放判断。
- OOM 的具体原因和可用最大环境数需要以远程 `nvidia-smi` 与短试验确认。
- 平台的真实物理高度和机器人可爬高度不能只凭 Viser 画面确定，当前 150 mm/300 mm 是配置值，实测值待确认。

## 2026-10-30：用户澄清与排查优先级

- 观测历史已澄清：原始Lego2配置关闭actor高度扫描；用户后来注释掉删除语句。
  后续恢复盲走是恢复原始输入约束，不能把当前修改版本混同原始项目。
- checkpoint编号9999的全量策略在多次回放中均失败，表现为前轮不抬、后腿反抬。
  不再优先以早期短训样本不足解释该反馈，也不依据奖励均值认定正确抬腿已学会。
- 后续实施前加入最小足端索引/动作映射/关节符号/目标限幅与运动学核对，
  目的是先排除接口或可达性问题；没有证据时不得直接交换前后腿或翻转关节符号。
- 仍处方案探索阶段；用户未要求实施，本轮不修改奖励、地形、观测或算法，不训练。
