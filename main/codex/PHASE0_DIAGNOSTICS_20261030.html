阶段0：动作、足端与CPU响应诊断#

日期：2026-10-30（Asia/Shanghai）。源码根目录： /home/asus/work/mjlab_lego2_work。

状态：诊断工具、名称映射、CPU运动学和原生MuJoCo PD本地验收通过； 远程同步/校验待执行，Warp动态接触与旧策略轨迹待确认。 阶段1尚未实施，本批无PPO训练。依据为正式计划阶段0； 用户本轮明确授权从阶段0开始实施，取代上一轮仅做文档核查的临时边界。

1. 改动和回退#

  • 新增诊断工具及 集成测试。

  • 新增本记录、原始数值、 远程同步/校验说明并维护连续性文档和changelog。

  • 原文件在批前备份， 按源码相对路径保存。该工作副本没有可用Git元数据，因此以备份和SHA-256核对。

  • 与批前清单比较，原有434个源码/测试/资产/依赖文件逐字节不变。 未修改旧三任务、共享资产、PPO、奖励或训练产物，也未连接远程执行操作。

原始JSON包含实际加载的源码/资产hash、名称索引、目标探针、逐关节扰动、 运动学扫描及逐控制帧PD轨迹；不能用本地结果代替远程结果。

2. 核心代码如何工作#

build_inspection()从当前Platform-Climb训练配置复制一个独立诊断scene， 只把地形换成z=0平面、环境数设为1，保留机器人、动作、足端传感器声明和仿真选项。 它不创建PPO、奖励、课程或随机化manager，也不改原任务配置。

Inspection.control()依次调用真实的ActionManager分片、ActionTerm缩放/偏置、 Entity目标写入和built-in actuator路由，再读取实际ctrl。没有另外手写一套 动作映射来“证明”自己的映射。实际target_names/target_ids和actuator传动joint 会互相核对，发现不一致直接报错。

perturb_joints()保持root和其他关节不动，逐关节±0.1 rad计算轮心位移； scan_front_legs()扫描两前腿的HFE/KFE组合。轮底使用碰撞圆柱的真实中心和 世界轴向支撑距离计算，包含轮轴倾斜影响，不把轮心高度当净空。

扫描分别记录raw∈[-1,1]比较窗口、软范围、硬范围。随后在临时模型中加入 3/15/30 cm台阶，只对选出的软范围姿态检查接触穿透。完整扫描未逐姿态过滤碰撞； 静态无穿透也没有证明接近路径、驱动力或承重稳定性。

pd_trials()每次重新落地0.5 s，再独立执行0.4 s中立/收前腿/收后腿探针。 前腿raw为HFE=+0.5、KFE=-1，后腿镜像为HFE=-0.5、KFE=+1；轮速目标均为0。 这是诊断输入，不是准备写进策略的手工轨迹。每帧保存动作、目标、实角/实速、 力矩、root、轮底和水平/竖直地面接触力；饱和率按每个物理步统计。 响应/力矩/饱和汇总只覆盖0.4 s脉冲段，0.5 s落地段仅保存其结束时轮位作为基线。

5. 前腿可达范围与实际响应#

扫描条件：root固定(0,0,0.47)、姿态单位四元数；地面z=0；轮半径0.115 m。 默认轮底高48.10 mm，落地后不能继续沿用这个悬空初始条件。 假想台沿在root前方x=0.5 m，要求整个轮子越过该竖线且轮底高于台面1 cm。 这个位置是诊断几何参数，不是训练奖励或实际受阻root位置。

6. 已完成的本地验证#

全部使用既有.venv和uv run --no-sync，无依赖安装/锁文件改动：

  • 新工具与测试的Ruff格式、lint、Pyright、ty、compileall通过。

  • 5项诊断集成测试及Lego2资产编译：6 passed, 2 deselected。

  • 完整41点诊断已保存，含6个台阶静态姿态检查及3条PD试验轨迹。

  • 三个旧任务的train/play共6个配置及3个agent配置可加载；注册仍只有原三个Lego2任务。

  • 434个已有源码/资产/测试/依赖文件与批前SHA-256完全相同。

当前受限执行环境无法访问CUDA；本批动态部分是原生MuJoCo CPU，未执行Warp step、 GUI、PPO或checkpoint回放。Warp初始化提示无CUDA、圆柱碰撞对的MULTICCD支持警告 已如实记录，不能据CPU接触结果认定GPU接触已通过。

list-envs控制台入口把任务数量当退出码（源码main返回数量）；验证使用 uv run --no-sync python -m mjlab.scripts.list_envs --keyword Lego2正常退出。 未为此修改原脚本。缓存目录通过本次命令环境变量放在/tmp，不改用户全局配置。

7. 下一步#

先按远程说明备份、同步和核验本批明确文件， 检查当前业务源码/资产hash并只读归档旧run文件清单。远程尚未执行，不能标记已同步。 核验结果一致后进入阶段1独立盲走任务/原生历史，继续逐批讲解和本地验收。 少环境Warp动态接触在后续环境验收中补验；旧9999策略的真实动作、碰壁水平接触、 目标越限和力矩饱和仍待轨迹证据，不据本批探针指定旧训练失败的唯一原因。
