Lego2 高台攀爬项目上下文#

本文件保存长期项目事实；当前阶段和同步状态见 CURRENT_STATUS.md。 跨会话唯一交接入口为 HANDOFF.md，维护规则见 AGENTS.md。

更新时间：2026-10-31（Asia/Shanghai）。

项目目标与平台#

目标是让 Lego2 四足轮足机器人依靠本体感知稳定越过高台，既有目标参考为300 mm。 任务已明确为盲走：部署 actor 不读取高度扫描、地图位置或训练接触真值； critic、奖励和评估可以使用训练特权信息。其他机器人80 cm演示不证明Lego2可达同一高度。

原始Lego2配置关闭actor的height_scan。用户后来注释了删除扫描的语句， 使修改后的Rough/Platform-Climb保留扫描；不能将这一修改说成原始设计。 新路线的选择依据和适用状态由 DECISIONS.md 管理； 具体设计与验收参数查阅 REFACTOR_PLAN.md，不从本页推断已实现阶段。

框架与总体架构#

  • 环境：mjlab ManagerBasedRlEnv，以manager组织观测、动作、指令、事件、奖励、课程和终止。

  • 仿真：MuJoCo + MuJoCo-Warp；原生CPU诊断与Warp动态接触验证属于不同证据。

  • 强化学习：RSL-RL PPO，现有actor/critic为MLP；配置入口为 lego2_ppo_runner_cfg()。

  • 控制：8个腿关节位置目标＋4个轮关节速度目标，控制周期0.02 s。 任务配置的腿/轮scale为0.45/5；缩放不等于动作裁剪。

  • 机器人实际加载：lego2_constants.py:get_spec() → xmls/lego2.xml。 URDF不是训练时的实时转换入口；两格式的资产修复需要分别保持一致。

  • Rough、Flat和Platform-Climb共享机器人资产，资产变化可能影响三个任务。

控制与PPO默认配置速查#

本节整合自旧核心代码解析，并于2026-10-31只读核对 env_cfgs.py和rl_cfg.py。下表是当前源码默认值，不证明任一历史run实际采用它们； 运行配置仍须查该run的params/env.yaml和params/agent.yaml。

配置

当前默认值及含义

腿/轮控制

腿为位置目标，轮为速度目标；动作、物理关节目标和观测缩放是不同量

actor观测缩放

角速度0.25、腿关节位置偏差1.0、关节速度0.05；旧任务当前保留扫描的原因见前文

actor / critic

均为512→256→128 MLP，ELU，启用观测归一化

探索分布

GaussianDistribution，初始标准差1.0，scalar标准差类型

PPO更新

clip_param=0.2，5个learning epochs，4个mini batches

学习率与探索项

learning_rate=1e-3，adaptive schedule，entropy_coef=0.01

折扣与GAE

gamma=0.99，lam=0.95

更新约束

desired_kl=0.01，max_grad_norm=1.0，value_loss_coef=1.0，use_clipped_value_loss=True

rollout与保存

每环境每轮24步；save_interval=50，默认max_iterations=10000；不据此猜测实际模型编号

采样量按“环境数×每环境rollout步数×实际完成的更新轮数”理解。 以24步rollout为例，4096环境每轮98,304条、256环境每轮6,144条； 若4096环境确实完成10,000轮，理论总量为983,040,000条，而非实际完成量的证明。

旧解析里的腿scale常量0.25、旧奖励表及rl_cfgs.py写法属于历史描述； 当前生效腿scale与实际文件名分别见前文及关键路径表。 这些历史说明不作为新盲走任务的已实现配置，也不据奖励正负名称推断函数语义。

历史已确认的本地环境为Ubuntu 22.04、RTX 4060 Laptop GPU（8 GB）、 项目隔离的uv .venv、Python 3.13.16、PyTorch 2.9.0+cu128、MuJoCo 3.11.0。 这些是既有记录，不代表每个执行环境都能访问CUDA；当次能力和验证范围记录在CURRENT_STATUS。 远程GPU为RTX 4090（24 GB），可用显存需在实际试训前确认。

旧Platform-Climb通过deepcopy派生自Rough，保留独立注册： Mjlab-Platform-Climb-Lego2；另有 Mjlab-Velocity-Rough-Lego2、 Mjlab-Velocity-Flat-Lego2。新任务的实施和注册状态只查CURRENT_STATUS。

独立入口Mjlab-Blind-Pit-Lego2使用lego2_blind_pit_env_cfg()，日志名 lego2_blind_pit。actor与critic分别deepcopy，避免基础工厂共享term造成历史污染。 actor按角速度/重力/腿位置/全关节速度排列，各5帧；动作12维和xz命令2维只保留当前值。 原生历史按term-major、各term内旧到新拼接，actor共144维；部分reset按环境回填新首帧。 train/play共用工厂，play关闭actor噪声及高度课程。保持12维动作和现有PPO参数， 不直接加载旧checkpoint继续训练；阶段验收及是否具备开训条件以CURRENT_STATUS为准。

新任务地形由十行独立10×10 m地块组成，每块中央3×3 m单级坑，深度3～30 cm。 origin已在坑底，出生采用origin加默认root高度0.47 m，无二次减深度。 20 s episode保持固定vx命令，heading反馈修正yaw；训练从等级0开始。 blind_pit_curriculums.py提供独立课程和局部边界：按名称匹配轮子/接触， 用完整轮包络、轮底/接触点高度及向下接触法向确认坑沿支撑，再按单环境结果升降级。 课程只处理已终止episode；play关闭课程，中途手动reset不更新等级。 root超过局部4 m或轮子包络到达4.9 m时truncate，此信号不等于越障成功。

训练、续训与回放流程#

通常流程为：按批修改并解释核心代码 → Codex完成本地uv校验 → 用户按明确文件清单先备份、再同步并执行远程校验 → 配置与功能验收通过后在screen内按阶段试训 → 记录实际结果后决定下一步。 文档交接不会自动触发上述开发或训练。

  • 本地终端与远程SSH终端分开标注；远程通过 ssh -p 10395 ajifang@27.128.203.222 连接后进入 ~/zrq/mjlab_lego2。禁止未经核对的全目录覆盖或 rsync --delete。

  • 长训练固定screen名 zrq：先 screen -ls；存在时 screen -r zrq， 不存在才 screen -S zrq。用Ctrl-A、D脱离会话。

  • 相同配置续训先确认实际checkpoint；Tyro布尔参数为 --agent.resume True， 不能写小写true。--agent.load-run、--agent.load-checkpoint取自真实日志文件。 不保证Ctrl-C恰好保存中断时的迭代，只能从实际存在的checkpoint恢复。

  • 观测/奖励/地形/资产变化须按相应技术决策核对新run和版本归属， 不把旧checkpoint与新配置混成一个可比较实验。
